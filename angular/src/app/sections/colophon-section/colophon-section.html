How This Site Is Built

A footnote for the curious. This is the Angular edition of mvcprogrammer.com: the same content and the same stylesheet under its own palette, with the page rebuilt as Angular components in TypeScript. There is still no server behind it, only static files on a CDN, three Lambdas, and the same API.

Front end
An Angular 22 application: standalone components, signals, OnPush change detection, and no zone.js. Each section of the page is a component; the header, the skill filter, the kiosk demo, and the contact form hold their state in signals and a reactive form. The static edition's 470 lines of JavaScript became about the same amount of TypeScript, now split by component, typed against the API's contract, and covered by tests. There is no separate script: the components reach IntersectionObserver, matchMedia, and the native <dialog> directly.
Shared with the static site
The stylesheet, fonts, images, icons, and the Experience seed data are copied into this build from the repository root by a script that runs before every build, so the editions cannot drift. The markup is the static page's markup, section by section. Component styles are not used: Angular would inject them inline, which the Content Security Policy forbids, so the few additions sit in one extra stylesheet. That file also carries this edition's palette, navy and brass, by overriding the shared design tokens with light-dark(); no rule from the shared stylesheet is repeated.
API integration
The work history is read from the same Experience API (/api/experience and /api/skills) through HttpClient over fetch, with an explicit timeout on every request and TypeScript interfaces that mirror the OpenAPI contract. CloudFront routes /api on this subdomain to the same Lambda, so the calls stay same-origin. If the API is unreachable the timeline renders from a bundled copy of the seed file.
Configuration
The Lambda URLs and API paths are one typed options object, validated at startup and provided through an injection token. The two HTTP clients and the contact topic state are registered in one provideSite() function behind abstract classes, so components depend on the contract and tests swap in fakes.
Hosting
The build output sits under an angular/ prefix in the same private S3 bucket as the static site, read by a third CloudFront distribution through Origin Access Control at angular.mvcprogrammer.com, with its own ACM certificate and Route 53 alias. Unknown paths fall back to index.html so the Angular router answers them.
Security
The same strict response headers as the static site, Content Security Policy included, with no change: Angular needs no inline script, no inline style, and no eval. Critical-CSS inlining is switched off in the build for the same reason. There is still nothing third-party, no cookies, and no analytics.
Payload
The production build is tree-shaken and minified by esbuild into a handful of fingerprinted files that the browser caches for a week and CloudFront compresses on the fly. The app, framework included, is a fraction of the size of the .NET runtime the Blazor edition downloads.
Deploys
The GitHub Actions workflow that deploys the static site also runs the Vitest suite and ng build for this project, syncs the output to the angular/ prefix, and invalidates this distribution. Same OIDC role, no stored AWS keys.
Tooling
Written in JetBrains Rider with Claude Code as a pair programmer, and previewed locally with ng serve before each commit.
